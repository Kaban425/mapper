# Исследование: Mapper — оверлей-линейка для карты PUBG: BATTLEGROUNDS

**Решение: CONDITIONAL GO · Уверенность: Medium · 2026-10-20**

> Шаг 2 RPI-воркфлоу. Вход: `rpi/mapper-overlay/REQUEST.md`. Отчёт собран из шести фаз:
> разбор требований, продуктовый анализ, две ветки технической разведки
> (факты PUBG и Tauri/Windows), техническая оценка и стратегическая оценка.
> Где оценки фаз 3 и 4 расходятся, действует решение фазы 4.

## 1. Executive Summary

Mapper стоит делать. Ниша реальная: на GitHub десятки инструментов для миномёта в PUBG, но
лидер набрал 19 звёзд, и ни один не работает поверх живой карты без захвата экрана, хуков
или отправки ввода в игру. Технически всё ядро (математика, данные, упаковка, CI) делается
уверенно. Неизвестное одно: надёжно ли прозрачное окно Tauri забирает клики и клавиши у
игры в режиме Borderless так, чтобы на карте игры ничего не менялось. Поэтому решение
условное: перед `Plan` нужен одноразовый спайк S-1 (фокус и захват ввода) и спайки S-2,
S-3 (показ/скрытие окна и производительность). Если S-1 провалится, есть запасной вариант A′
без перехвата мыши. Остаточный риск бана честно делится на две части: риск обнаружения низкий,
риск по правилам ненулевой и неустранимый. Автор принял эту формулировку 2026-10-20.

## 4. Продуктовый анализ

### 4.1 Ценность по сегментам

| Сегмент | Задача | Ценность |
|---|---|---|
| Миномётчики (основной) | Попасть первым снарядом по точке на карте | High |
| Squads/duos в Normal | Успеем ли до зоны, далеко ли машина | Medium |
| Новички | Почувствовать масштаб карты | Low–Medium |
| Ranked/esports | Избегают сторонних программ, турниры их запрещают | Low |
| Стримеры | Охват есть, но риск; при Game Capture оверлей не попадёт в эфир | Low |

Подсчёт клеток по диагонали занимает 5–15 с при ошибке ±25–50 м, для миномёта это промах.
В Mapper замер — два клика, 2–3 с. Без зума на карте 8×8 при 1080p получается около 7,4 м/px,
то есть ±10–15 м (при условии, что карта занимает всю высоту экрана, это ещё не проверено).
С зумом и калибровкой ±2–5 м. Отсюда правило UX: рядом с числом показывать «±N м», а в
режиме миномёта при крупном м/px подсказывать «увеличьте зум и откалибруйте».

### 4.3 Чем выделяется Mapper

1. **Проверяемая безопасность.** Нет захвата экрана, хуков, `SendInput`, прав администратора.
   CI-guard проверяет запрещённые API и импорты, это видно из README.
2. **Работает поверх живой карты.** Видны свои метки и зона, alt-tab не нужен.
3. **Честная точность.** «±N м» и источник масштаба под каждым числом.
4. **Полировка.** HUD-дизайн, DPI и ultrawide, RU/EN, portable и установщик, SHA256.
5. **Открытые данные.** Пресеты карт в JSON, новую карту сообщество добавит через PR.

### 4.4 Соответствие ограничениям

Dev Letter наказывает неразрешённые программы «regardless of name or form», поэтому нулевого
риска нет ни у одной функции. Задача — чтобы каждую функцию можно было защитить как «линейку».

| FR | Статус | Решение |
|---|---|---|
| FR-1, FR-7 оверлей | Риск восприятия | Окно по форме похоже на внешний ESP. Вне замера оно скрыто, а не просто прозрачно |
| FR-2, FR-13 хоткей | OK | Только `RegisterHotKey`, права admin не запрашивать |
| FR-3–FR-7 | OK | Всё строится на кликах игрока и публичном размере сетки |
| FR-8 угол по клику | Неоднозначно | Больше всего похож на прицеливание, зависит от непроверенного FOV. Перенесён в v1.1, по умолчанию выключен |
| FR-9, FR-10 | OK | Физика и публичная дальность миномёта |
| FR-11 время | OK | Знак «≈» и указанная скорость. В игре есть Spotter Scope с дальномером до 1 км |
| FR-16 обновления | OK | Единственный сетевой запрос, с переключателем |
| FR-17 монитор | Риск | Окно игры не ищем. Монитор под курсором при нажатии хоткея |

**UX-правила «линейки»:** не использовать слова aim, assist, auto, bot, radar; ничего не
рисовать без клика игрока; не хранить историю матчей; под числом показывать источник.

### 5.3 Миномёт

- Дальность **121–700 м** (Update 14.2, ноябрь 2021), подтверждено. W/S — грубый шаг ствола,
  колёсико — точный. На Haven миномёта нет. Изменений в 2025–2026 не найдено.
- В Ranked статус неясен: в Season 14 исключён, в заметке Update 30.2 упомянут как полезный в
  Ranked. Противоречиво.
- Что показывает прицел и какой у него шаг — не подтверждено.

**Формула** (из `PUBGMortar/Services/MortarCalculator.cs` проекта PUBGMortar.NET):

- `M = 700` м — максимальная дальность на ровной местности (для модели без сопротивления
  воздуха это v²/g).
- `L` — горизонтальная дистанция по карте, `β` — угол на цель (вверх положительный),
  `t = tan β`. Для ручного ввода высоты `t = Δh / L`.
- Если `|β| < 0.001`, то `R = L`.
- Иначе `δ = M² − 2·L·M·t − L²`. При `δ < 0` решения нет (цель вне досягаемости).
- Значение для прицела: `R = (L + t·(M − √δ)) / (t² + 1)`.

Смысл: это решение навесной траектории без сопротивления воздуха. Число на прицеле считается
дальностью на ровной земле для текущего угла ствола. Пример: L = 400 м, цель на 5° выше
(≈35 м) даёт R ≈ 412 м. Вверх нужно больше, вниз меньше. Алгебра проверена, совпадение с
игрой не подтверждено (G-2).

**Угол по пикселям** (для FR-8, v1.1): в коде `β = atan(Δy · tan(vFov/2) / (H/2))`, то есть
прямолинейная проекция. README того же проекта описывает линейную зависимость и противоречит
коду. Для Hor+ вертикальный FOV нужно считать от базы 16:9: `vFov = 2·atan(tan(hFov/2)·9/16)`.
PUBGMortar.NET берёт реальное W/H и поэтому ошибается на 21:9 и 16:10. Ещё одно расхождение:
README даёт +26,19° для верха экрана при 1440p, а формула при HFOV 80° даёт 25,27°
(26,19° соответствует HFOV ≈ 82,3°).

### 5.6 Античит и оверлеи

- Krafton использует собственный античит Zakynthos (с 2023), с Update 37.1 (август 2025)
  добавлена проверка ядра при запуске, с конца 2025 — обнаружение kernel-драйверов и DMA.
  Подтверждено. BattlEye по сторонним спискам ещё используется, возможно устарело.
- Дорожная карта 2026: DMA-читы, AI-разбор видео, блокировки по железу. Об оверлеях ничего.
- Rules of Conduct: перманентный бан за «unauthorized programs or hardware devices that are not
  permitted by KRAFTON that promote unfair game play». Примеры — особые мыши и DMA-платы.
- Официальных заявлений про topmost-окна, линейки, калькуляторы миномёта и оверлеи Discord,
  NVIDIA, Overwolf нет. Прецедент 2018 года: ReShade блокировали при запуске, а не банили.
- Overwolf: 19 приложений для PUBG, одно отмечено на developer.pubg.com, официального белого
  списка нет.
- Запускается ли PUBG с правами администратора — утверждает только README PUBGMortar.NET,
  не подтверждено. Обычно игра идёт через Steam без повышения.

**Окно оверлея:** `transparent`, `decorations:false`, `alwaysOnTop`, `skipTaskbar`, `shadow:false`,
`focus:false`, `visible:false`, `resizable:false`, `noRedirectionBitmap:true` (без белой вспышки);
`html, body` с прозрачным фоном. Особенности tao:

- любая смена флага переписывает весь `GWL_EXSTYLE`, свои биты пропадают;
- `skipTaskbar` не убирает окно из Alt+Tab, `WS_EX_TOOLWINDOW` нужно ставить самим после каждой смены стиля;
- click-through только для всего окна, по пикселям не будет;
- у части пользователей (≈5%, данные Electron) полноэкранное прозрачное окно становится чёрным, помогал размер на 1 px меньше экрана;
- topmost-окно остаётся поверх Borderless; эксклюзивный fullscreen вне рамок.

**Фокус:** `focusable:false` не пропускает клавиатуру в WebView2, поэтому в замере окно должно
получать фокус. **Ловушка:** `set_focus()` в tao при неудаче `SetForegroundWindow` эмулирует
нажатие Alt через `SendInput`, то есть шлёт ввод в игру. То же делает создание окна с
`fullscreen`. Оба пути запрещены. `WM_HOTKEY` даёт процессу право вызвать `SetForegroundWindow`
напрямую.

**Горячие клавиши:** `global-hotkey` (основа плагина) использует `RegisterHotKey`, но после
нажатия опрашивает `GetAsyncKeyState` каждые 50 мс, пока клавиша зажата. Модификатор (Alt)
доходит до игры, основная клавиша поглощается. Если игра запущена от администратора, UIPI
блокирует хоткей. Колёсико с модификатором — только Shift: Ctrl+колёсико масштабирует WebView2.

**DPI:** у монитора есть `position()`, `size()` в физических пикселях и `scale_factor()`. Позицию
и размер задаём в физических единицах, после переезда на монитор с другим масштабом размер
задаём повторно. Клик: `clientX × devicePixelRatio`.

**Производительность:** каждый WebView2 — это процессы browser, GPU и renderer; по памяти Tauri
близок к Electron, мерить нужно на деле. Borderless-игра с flip-model может работать в режиме
Independent Flip. Любое видимое окно сверху заставляет DWM композировать кадр, что добавляет
задержку. Поэтому в простое оверлей скрыт. `backgroundThrottling` работает только на macOS.

**Упаковка:** NSIS (кросс-сборка возможна); `webviewInstallMode: embedBootstrapper` (+1,8 МБ);
сам exe из `target/release` переносимый (ресурсы внутри, VC runtime статически), но Tauri
официально portable-режим не поддерживает, данные пишутся в `%LOCALAPPDATA%`. Подпись: EV
больше не даёт мгновенной репутации SmartScreen; Azure Artifact Signing для частных лиц только
в США и Канаде; SignPath Foundation бесплатен для OSI-проектов, но требует существующий релиз,
сборку в CI, MFA и политику подписи, и запрещает «hacking tools».

**Проверка обновлений:** `GET /repos/{owner}/{repo}/releases/latest`, без авторизации 60 запросов
в час с IP. Запрос из Rust (`ureq` + rustls + User-Agent), не чаще раза в сутки, с ETag.
WebView2 доступа в сеть не получает.

**Опыт других проектов:** overlayed (Tauri + React, оверлей Discord) — проблемы в основном на
Linux; electron-overlay-window следит за окном игры по заголовку (мы так не делаем);
HideNStick Notes (Tauri 2) — устаревший кадр при показе, мерцание при ресайзе, пропадающий
`WS_EX_TOOLWINDOW`, зависшие `msedgewebview2.exe` блокируют папку данных.

## 6. Технический анализ

### 6.1 Архитектура

| Окно | Создаётся | Флаги | Назначение |
|---|---|---|---|
| `overlay` | при старте, скрыто | как в 5.7, `focusable:true`, размер монитора −1 px, никогда `fullscreen` | замер и калибровка |
| `hud` | при первом результате | ≈320×140, click-through, `focusable:false` | результат, скрывается через ≈10 с |
| `settings` | по запросу, уничтожается при закрытии | обычное окно | настройки, «О программе» |

Single-instance без плагина (он импортирует `FindWindowW` и `GetWindowThreadProcessId`):
named mutex и named event «открыть настройки».

- **Rust (≈600–900 строк):** горячие клавиши (своя обёртка `RegisterHotKey`), фазы окна и фокус
  (`platform/win/focus.rs` — единственный файл с `unsafe` Win32), позиционирование по монитору
  под курсором, конфиг, проверка обновлений, tray. Тесты `cargo test`: парсинг хоткеев,
  миграция конфига, semver, геометрия мониторов.
- **TypeScript (`src/lib/core/`):** вся математика чистыми функциями. Расчёт идёт на каждое
  движение мыши, IPC добавил бы задержку; `number` — тот же f64. Тесты vitest с порогом 80%
  (цель 95%) и fast-check для свойств. Эталонные векторы в `tests/golden/*.json` переносятся,
  если понадобится вариант B.

**Машина состояний.** Rust владеет фазой окна: `Hidden → Activating → Active → Deactivating →
Hidden`, хоткей во время перехода игнорируется. Фронт ведёт режим через чистый
`transition(state, event)`:

- `Idle` → хоткей → `MapMeasure`; если масштаба нет, сразу `Calibrate`.
- `MapMeasure`: ЛКМ — точка, ПКМ — убрать последнюю, колёсико — Δh ±1 м, Shift+колёсико —
  ±10 м, `C` — `Calibrate` и обратно, Esc или хоткей — `Result`.
- `Result` уходит в HUD, по таймауту или хоткею — `Idle`.
- `MortarAngle` (v1.1, под флагом) — из `Result` по второму хоткею.
- Потеря фокуса в любой активной фазе: окно сразу становится click-through и переходит в
  `Result`. Окно без фокуса никогда не перехватывает мышь.

**Данные и конфиг.** `src/data/maps.json` (`id`, `names`, `nominalKm`, `worldExtentM`,
`gridMajorM: 1000`, `gridMinorM: 100`, `gridVerified: false`, `source`) и `speeds.json`
(`mps` или `kmhTypical`, `kmhTop`, `source`, `confidence`); `dataVersion` в «О программе»,
схема проверяется тестом. Конфиг — serde-структура в `app_config_dir()/config.json` со
`schemaVersion`, запись атомарная, битый файл уходит в бэкап. Калибровка при зуме живёт в
сессии, базовая калибровка минимального зума хранится по ключу разрешения монитора.

### 6.2 Как решены противоречия

**a) Скрывать оверлей в простое — да.** Скрытое окно не композируется, Independent Flip
сохраняется, и со стороны это не похоже на ESP. Чтобы при показе не мелькнул старый кадр,
последний кадр перед скрытием всегда пустой:

1. Выход: Rust включает click-through и возвращает фокус игре.
2. Фронт отдаёт результат в HUD, очищает DOM, ждёт два кадра и сообщает `overlay_blank`.
3. Rust скрывает окно по этому сигналу или через 150 мс и снижает активность WebView2.
4. Вход: показать окно, взять фокус, фронт рисует интерфейс через 1–2 кадра. Старый кадр
   прозрачный и не виден.

Если при смене монитора появится чёрный или белый кадр, переход делается под `DWMWA_CLOAK`.
Спайк S-2 сравнит три варианта: hide/show с пустым кадром, cloak, окно всегда показано.

**b) Фокус без `set_focus()`.** В обработчике хоткея на главном потоке: запомнить
`GetForegroundWindow()` как непрозрачный HWND (ничего о нём не спрашиваем) → поставить окно на
монитор под курсором → `show()` → после этого `SetForegroundWindow(overlay)` и проверить, что
фокус наш, при неудаче повторить через 30 мс. Если фокус не взят, показываем «кликните, чтобы
начать»: первый клик активирует окно и точку не ставит, через 3 с без активации — выход. На
выходе фокус возвращается сохранённому окну, затем оверлей скрывается. У оверлея гасим
`SC_KEYMENU`, иначе отпускание Alt после Alt+Q включит меню окна и съест Esc.

**c) Масштаб.** Основной путь — калибровка: шаг 1 км (по умолчанию) или 100 м, колёсико задаёт
число клеток 1–8, затем два клика по линиям сетки. Масштаб = `N·шаг / max(|dx|, |dy|)`: линии
сетки идут по осям, поэтому неровный клик не портит результат. Поверх рисуется «призрачная»
сетка, по которой игрок сам сверяет совпадение (экран при этом не анализируется). Погрешность
показывается как «±N м» (ошибка клика ≈1,5 px × м/px × √2 плюс ошибка масштаба). Авто-пресет
«карта на всю высоту экрана» — бета с `verified:false` до проверки G-1. Если клетка окажется
1020 м (+2%, ≈14 м на 700 м), правится `gridMajorM` в JSON без изменения кода.

**d) Угол по клику (FR-8).** Решатель `R(L, β)` входит в v1.0, он нужен и для Δh колёсиком.
Интерфейс угломера переносится в v1.1 под флаг: разница FOV 80 и 90 даёт около 19% ошибки
масштаба угла (≈9 м при L = 600 м и β = 5°), FOV вида миномёта неизвестен, клик по цели в
3D-виде выглядит как прицеливание.

**e) Горячие клавиши (решение фазы 4).** Фаза 3 считала `GetAsyncKeyState` в `global-hotkey`
приемлемым. Фаза 4 решила иначе: это типичный API кейлоггеров, а отслеживать отпускание
клавиши Mapper не нужно. Своя обёртка над `RegisterHotKey` (≈150 строк) входит в v1.0,
плагин не используется.

**f) Сборка (решение фазы 4).** Portable .exe и установщик NSIS. MSI не делаем: он требует WiX
и ничего не добавляет к решению автора «portable + установщик».

### 6.3 Anti-ban guard

Проверка работает локально (`npm run guard`) и блокирует CI.

1. **Исходники** (`src/`, `src-tauri/src`, `build.rs`, конфиги). Запрещённые группы:
   - ввод: `SendInput`, `keybd_event`, `mouse_event`, `BlockInput`, `SetCursorPos`,
     `ClipCursor`, `AttachThreadInput`, `SwitchToThisWindow`, `PostMessage`/`SendMessage`
     вне своих окон;
   - хуки и опрос клавиатуры: `SetWindowsHookEx`, `SetWinEventHook`, `RegisterRawInputDevices`,
     `GetRawInputData`, `GetAsyncKeyState`, `GetKeyboardState`;
   - процессы: `OpenProcess`, `ReadProcessMemory`, `WriteProcessMemory`, `EnumProcesses`,
     `CreateToolhelp32Snapshot`, `QueryFullProcessImageName`, `NtQuerySystemInformation` и т.п.;
   - чужие окна: `FindWindow`, `EnumWindows`, `GetWindowText`, `GetClassName`,
     `GetWindowThreadProcessId`, `WindowFromPoint`; `Get/SetForegroundWindow` разрешены только
     в `focus.rs`;
   - экран: `BitBlt`, `PrintWindow`, `GetDC`, `GetPixel`, `GetDIBits`, Desktop Duplication,
     `Windows.Graphics.Capture`, `DwmRegisterThumbnail`, Magnification; в JS `getDisplayMedia`,
     `getUserMedia`, `html2canvas`;
   - Tauri: `.set_focus(`, `setFocus(`, `fullscreen`.
2. **cargo-deny `[bans]`:** крейты эмуляции ввода и хуков (enigo, rdev, inputbot, device_query,
   winput, autopilot, willhook и др.), захвата экрана (xcap, screenshots, scrap, windows-capture
   и др.), процессов и памяти (sysinfo, process-memory, memflow, dll-syringe, retour, minhook),
   а также `tauri-plugin-shell`, `tauri-plugin-single-instance`,
   `tauri-plugin-global-shortcut`. Через `[[bans.features]]` запрещаются фичи `windows`:
   `Win32_System_Diagnostics_ToolHelp`, `Win32_System_ProcessStatus`, `Graphics_Capture`,
   `Win32_UI_Magnification` (сверить с `cargo tree -e features` на скаффолде).
3. **npm:** в `package-lock` нет robotjs, @nut-tree*, iohook, uiohook-napi,
   node-global-key-listener, screenshot-desktop, `@tauri-apps/plugin-shell`.
4. **Tauri ACL:** snapshot-тест `capabilities/*.json` — нет `allow-set-focus`,
   `allow-set-fullscreen`, fs, shell, http.
5. **Импорты exe:** `dumpbin /imports` релизного файла сравнивается с
   `antiban/imports-baseline.txt`. Ожидаемое единственное исключение — `SendInput` из tao
   (путь `force_window_active` достижим только через `set_focus` или `fullscreen`, оба закрыты
   пунктами 1 и 4). Исключение описывается в README, в tao отправляется issue или PR.
   Полный список импортов tao и wry проверяется на скаффолде.

### 6.6 Альтернативы реализации

## 8. Формулировка риска для README

**RU.** Mapper — отдельная программа-линейка. Она не внедряется в игру, не читает её память,
файлы и процессы, не делает скриншотов и не нажимает клавиши за вас: все точки ставите вы сами
кликами, а расчёт идёт по сетке карты и публичным параметрам. Поэтому риск, что античит
технически примет Mapper за чит, низкий. Но правила PUBG запрещают любые неразрешённые KRAFTON
программы, которые дают нечестное преимущество, и официального разрешения или белого списка
для Mapper нет. Решение о том, стоит ли этот риск, принимаете вы. Не используйте Mapper в
турнирах; в Ranked — на ваше усмотрение. Mapper не связан с KRAFTON.

**EN.** Mapper is a separate ruler app. It does not inject into the game, read its memory, files
or processes, take screenshots, or press keys for you: you place every point yourself, and the
math uses the map grid and public game constants. This makes it unlikely that anti-cheat
technically classifies Mapper as a cheat. However, PUBG's rules prohibit any program not
permitted by KRAFTON that gives an unfair advantage, and Mapper has no official approval or
whitelist. Whether that risk is acceptable is your decision. Do not use Mapper in tournaments;
use in Ranked is at your own discretion. Mapper is not affiliated with KRAFTON.

| Неверные данные миномёта или сетки | автор | попаданий < 70% или клетка ≠ 1000 м → правка JSON, флаг experimental |
| Срыв сроков | автор | спайки > 4 дней или v1.0 > 23 дней → урезать анимации и доводку ultrawide |
